# G0：官方语义入口探针与接入边界（2026-09-23）

## 用户已确认的方向

**保留有限扫描器，独立重建核心。** 当前模式扫描器继续保持可运行；本轮只增加隔离实验和证据，没有修改 `src` 或恢复已删除的旧框架。

## 本轮交付与结论

已增加 [可复现探针](../experiments/frontend_contract/probe.py)，在一个真实 MoonBit 模块、三个包中编译并运行官方语义查询。[机器记录](metrics/frontend-capability-2026-09-23.json) 包含全部源文件、命令、输出和指纹。

**结论：官方 IDE 能提供部分可靠声明绑定，可作为受限前端的组件；目前还不能交付新核心所需的完整语义输入。G0 尚未整体验收通过。** 不把 JSON 响应或导航查询成功记作动态调用解析已经完成。

固定环境：moon `0.1.20260920`、moonc `v0.10.14+7d59c7ec9`、native 后端。`moon check` 退出 0（2 项可见性提示，0 错误）。编译通过后才使用 `--no-check`，完成后核实源文件没有变化。

### 查询事实

| 内容 | 实测输出 | 能怎样使用 |
| --- | --- | --- |
| 普通直接调用 | `fill(box, box)` 找到 `fill` 的声明 | 可作直接调用绑定输入，仍需先确认表达式确实属于支持的调用种类。 |
| 同名局部变量 | 分别找到第 12 行与第 14 行的 `box` | 可避免自行按名称猜遮蔽关系。 |
| 同名跨包函数 | 区分 `left/lib.mbt` 与 `right/lib.mbt` 的 `choose` | 可用包身份、源码路径、声明位置建立快照内的身份。 |
| 结构体字段与直接方法 | 分别找到字段声明和 `Box::read` | 可为受限的字段/方法适配提供声明依据。 |
| 局部引用 | 返回同一个 `box` 的两个实参位置和后续字段读取位置 | 证明引用查询可复用；并不直接证明完整堆别名集合。 |
| 类型显示 | `hover` 返回 Markdown 形式的 `Box` | 适合作为对照，不直接把文字当作规范 TypeId。 |
| 泛型方法 | `value.render()` 返回 `T : Render` 的约束位置 | 不是预期的 trait 声明，更不是具体 `Box::render` 目标；不能当实际调用边。 |
| 泛型函数调用 | 显示原始 `fn[T : Render]` 签名 | 未得到结构化实例化映射。 |
| 回调调用 | `f(value)` 返回形参 `f` 的声明 | 不提供该形参可能接收的函数集合。 |
| 默认参数 | 找到 `with_default` 声明 | 未导出缺省求值、实参与形参对应及其副作用。 |
| 错误出口 | 显示 `raise Boom` 签名 | 未导出抛错路径、catch 后继或错误发生时的堆状态。 |

14 项查询中 **13 项满足预先列出的响应预期**，泛型方法的声明位置预期不匹配，探针保留退出码 **1**。这是候选提取契约没有成立，不是对官方 IDE 功能正确性的判错。即使该预期今后匹配，也不等于完整前端通过。

### 批量符号索引

`moon ide gen-symbols --target native --no-check` 实际产生 **20 条记录，覆盖探针的三个包**，包含函数、类型、trait 与 trait 实现元数据。观察到的字段为：

```text
kind, path, pkg, tag, range, name_range, doc_range
```

多个不同声明使用相同 `tag`，不能把它当唯一符号 ID。索引没有给出表达式类型、语句体、参数绑定、CFG 或堆效果。不能因为返回了 trait 实现列表，就认为每个泛型调用的目标已经解析。

本次全部命令合计约 **2.72 秒**，其中 14 次逐位置查询约 **2.48 秒**。这是一次极小项目的测量，不能外推真实语料性能；批量请求和缓存生命周期仍需验证。

## 接入契约：哪些事实还缺

| 新核心需要的事实 | 当前可取来源 | 接入要求 |
| --- | --- | --- |
| 包和顶层声明位置 | 本次符号索引 | 固定目标后端、工具链和源码指纹；不依赖非唯一 tag。 |
| 支持范围内的声明绑定 | 本次 `peek-def` | 由语法种类限定合法查询；空响应、多义响应、约束/形参目标不得冒充确定调用。 |
| 规范类型及泛型实参 | 尚未验证到结构化出口 | 不能从 hover 文本临时重建完整类型系统。 |
| 指令求值顺序与实参绑定 | 需另做受限的官方 AST 降低，或取得相应 compiler 导出 | 不得从声明位置反推字段写入顺序；语法降低须用独立执行结果验证。 |
| 分支、正常/异常出口 | 尚未交付 | `raise` 签名不足以构造完整错误控制流。 |
| 稳定性与成本 | 只有固定小快照 | 变更源码必须重新检查，禁止复用旧位置；真实调用数量下重新测量。 |

推荐的快照身份组合是 `(module/package, relative-source-path, declaration-range, source-fingerprint)`。这只是适配器内部的候选身份规范；不承诺跨编辑稳定，更不替代堆对象身份。每次编译检查失败时应结束适配，不能消费残留语义文件。

## 下一项独立实验

限定为**非泛型普通函数、直接结构体方法、显式实参、局部绑定及顺序字段读写**。使用官方 parser 取得语法结构，官方查询提供已经实测的声明绑定，生成小 IR；不加入自有类型重建或回退。

最先贯通四个原 `.mbt` 对照：

1. 同对象双形参先写后读。
2. 同对象后写清理，并反转写入顺序。
3. 不同对象的安全对照。
4. 变量遮蔽，确保读写对应正确对象。

验收必须由源码自动产生 IR 并进入现有独立核心。手写 IR、人工填写生产绑定表或沿用旧污点摘要都不计通过。类型或绑定事实不足时明确拒绝；泛型、回调、默认参数和异常暂不进入这一步的支持声明。

这一步通过后再补入此前 G1 要求的返回、异常与递归；四项小实验通过不能直接批准 CWE-113 全链或生产迁移。当前有限扫描器继续承担模式提示，新核心输出和状态单独报告。

## 后续推进：受限源码到 IR 贯通（同日）

已新增 [独立适配实验](../experiments/frontend_adapter/README.md) 与 [机器记录](metrics/frontend-adapter-2026-09-23.json)。在固定 moon `0.1.20260920`、moonc `v0.10.14+7d59c7ec9`、parser `0.4.0` 下，五组真实 `.mbt` 源码先通过 `moon check`，再由官方 AST 的源码坐标和 `peek-def` 核实全部受支持的直接调用，自动降低为独立核心 IR。5/5 对照通过：同对象先写后读、同对象先脏后清及反序、不同对象、局部遮蔽。8 项适配器单测含格式变动、版本失配与未知分支语法拒绝。

这修正了上文“尚未取得任何顺序 IR”的时间点结论：**限定在上述小子集，现在已取得由真实源码生成的顺序 IR**。它仍没有可复用的完整类型/CFG/异常入口；泛型、回调、默认参数、跨包和真实安全 API 不在支持范围。`source`/`sink` 是实验的显式模型，不是生产漏洞规则。G0 只有受限子集通过，G1 安全链未通过，生产入口没有迁移。

官方 [parser 仓库 README](https://github.com/moonbitlang/parser) 自称高度实验性且不稳定。为避免语法更新造成静默语义漂移，适配器固定工具链和 parser 版本，保留每个样例的 AST 结构清单，遇到未知构造拒绝；`validate.py --baseline` 对新版结构与结果逐项比较。CI 加了固定版本 `frontend-contract` 工作；现有安装最新工具链的工作仍用于发现上游变化。升级需要人工审查差异、补测后更新版本和基线，不能仅因新编译器能解析就默认分析语义成立。

## 跨版本目标修正（同日）

用户明确要求检测使用**不同 MoonBit 版本**的项目，而不是把目标项目锁在分析器的构建版本。现已把受限适配器的构建工具链与目标项目的 `moon check`/`peek-def` 工具链分离。三个目标 moon 版本 `0.1.20260904`、`0.1.20260915`、`0.1.20260920` 的五组对照均通过，同一分析器的 AST 结构与发现结果一致。正式有限扫描器的便携 CWE-116 对照也在三版本下通过；详见[多版本矩阵](metrics/project-version-compat-2026-09-23.json)。

更重要的是矩阵还发现可复现的**编译器—parser 差异**：三个编译器均接受 `for (x, y) in ...`，但 parser `0.4.0` 拒绝。原扫描器会返回解析错误和退出码 2；新[严格入口](../scripts/scan_compatible.py)显式返回 `scanner_incomplete` 并保留其他文件的发现。这表明“该编译器版本可运行”与“此项目所有语法均被检测”是两层不同的承诺。当前只对受限子集和一条生产规则完成跨版本验证；后续需补可解析前端与完整规则回归，不能把版本矩阵当全面兼容认证。
