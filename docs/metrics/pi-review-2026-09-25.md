## 1. src/project_driver/path_identity.c — 无阻塞
- Windows 分支：`MultiByteToWideChar(…MB_ERR_INVALID_CHARS…)` → 拒绝 reparse point → `FILE_FLAG_BACKUP_SEMANTICS|FILE_FLAG_OPEN_REPARSE_POINT` 打开 → `GetFinalPathNameByHandleW`；`\\?\UNC\`→`\\…`、`\\?\` 前缀剥离的 `memmove` 长度计算（含 NUL 拷贝、length-6/-4）核对无误；小写盘符归一化正确。所有失败路径返回空 bytes，MoonBit 侧 `absolute()`（project.mbt:34-42）回退词法路径，属失败安全。
- POSIX 分支：`lstat` 仅放行 REG/DIR，末组件 symlink/FIFO 返回空 → 词法路径 → `snapshot_dir` 中 `file_size()`（lstat，非 REG/DIR 返回 -2）在 project.mbt:174-176 主动 fail（"snapshot cannot verify symlink…"）。与声明的“末组件 symlink/FIFO 留给 snapshot 拒绝”一致；中间目录 symlink 经 `realpath` 归一后若逃出 root，`file_plan` 的 `full.has_prefix(root+"/")`（project.mbt:135）会剔除该文件并导致 `scope_incomplete`，不产生假成功。

## 2. src/project_driver/supervisor.c — 无阻塞
- macOS `audit_isolate`：嵌套 supervise 经 `MOON_AUDIT_SUPERVISED_GROUP`==`getpgrp` 短路（不另建会话），保证编译客户端留在语义 worker 组；`audit_limit_memory` 的守卫（env 匹配 + `group>1` + `getsid(0)==getpgrp` + limit>0 + 初始采样）齐全，任一不满足返回 0 → main.mbt:14-21 输出 `semantic_memory_supervision_setup_failed` 并 exit 2，失败安全。
- 采样循环 `sampling_failed` 亦杀组并 `_exit(125)`（fail-safe 方向）；`proc_listpgrppids` 传 `sizeof(pids)`（字节）、`count>=4096`→EOVERFLOW、`ri_phys_footprint` 求和带溢出检查，均正确。诊断经一次有界 `write(STDERR_FILENO,…)`，事件含 `limit_bytes/observed_bytes/sample_gap_ms`，且 `MOON_AUDIT_MEMORY ` 前缀仅此文件产生，测试侧可区分（helper 的 marker 无 `limit_bytes` 字段）。
- Windows：KILL_ON_JOB_CLOSE job 由 supervise 包装进程独占句柄，子进程自动入 job，包装进程退出/被 `TerminateProcess` 即回收全树；`audit_limit_memory` 的 PROCESS_MEMORY job 嵌套叠加在 Win8+ 合法；`AssignProcessToJobObject` 失败即返回 0→125，无假成功路径。Linux：RLIMIT_AS + 嵌套组 env，与 `memory_budget()` 报告的 per_process/hard 声明一致。
