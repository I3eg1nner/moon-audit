# LLM evidence acceptance — 2026-09-26

This milestone improves evidence supplied for **existing scoped semantic findings**. It does not implement autonomous source browsing or new vulnerability discovery. Syntax hints without verified call information retain their original windows.

## Changes and local checks

The analyzer emits AST source ranges for completed IR functions/callbacks. The review helper matches a finding's exact reported path to one route, walks its IR `Call` graph through the first `Return`, and includes complete function/callback sources, unit identities, IR operations, raw binding records and declared models. The helper checks report consistency and the whole project input snapshot; it does not independently rerun binding or authenticate arbitrary reports.

Cross-file citations require a per-finding attachment ID and exact provided lines. Unknown or ambiguous identities, missing spans, changed/added/removed inputs, unsupported line endings and budgets are explicit gaps. Evidence remains `llm_unverified` and static errors/statuses remain intact.

- Native units: 103.
- LLM offline/HTTP tests: 71 (45 existing contract, 10 compiler-linked evidence, 16 HTTP).
- Extracted optional API helper: 16 tests.
- Compiler contexts: 7 cases.
- Extracted analyzer plus extracted review helper: 4 real-compiler cases, including a helper longer than the old +/-12-line window, same-name fake encoder, cross-finding citation rejection, helper changes and constrained budget.

`local-acceptance.json` records binary/helper hashes; compressed raw reports are `compiler-context-acceptance.json.gz` and `llm-context-acceptance.json.gz`. Independent review found and closed Unicode line splitting and function-to-source range inconsistencies; NUL snapshot errors and empty-bundle prompt limits are covered too.

## Two authorized real API requests

`live-comparison.json` records two successful single-attempt calls using the same `.env` configuration and same static report. Credentials, endpoint and model name are not published. The isolated source is generated by `scripts/llm_context_test.py` using the fixed reviewed mocket dependency. Only three static positive findings were reviewed; safe routes were excluded by the static analyzer.

| Observation | Source windows | Compiler-linked evidence |
| --- | --- | --- |
| Reviews accepted | 3 | 3 |
| Verdict | 3 needs_review | 3 supported_concern |
| Cross-file exact quotes | 0 | 5 |
| Prompt tokens | 3,040 | 13,219 |
| Total tokens | 6,805 | 17,807 |

With windows, all three reviews lacked helper behavior. With attachments, the model cited actual helper sources and correctly described relay/markup concatenation, an identity function named `escape_html`, and swapped parameters. It retained missing runtime registration, middleware and responder behavior as assumptions. These are observable improvements in these explanations, **not a measured gain in overall precision or recall**. One run per variant, three positive findings, provider randomness and unequal token contexts do not support such a claim. Stronger verdict labels alone are not acceptance criteria.

The baseline was prepared with the previous release helper. Both calls use the same current API client and prompt renderer, so the baseline already includes the reported dataflow; this comparison isolates the new source/IR context more closely than comparing unrelated prompts.

## Reproduce without an external service

```sh
python3 -m unittest discover -s tests/harness -p 'test_llm*.py'
python3 scripts/llm_context_test.py --analyzer dist/extracted/moon-audit \
  --review-script dist/extracted/extras/llm_review.py \
  --corpus "$MODEL_CORPUS/mocket" --output /tmp/llm-context-acceptance.json
```

All three native delivery CI jobs run the second command against their extracted artifacts. External API calls are never part of CI. See [user documentation](../../docs/llm-review.md) for the explicit `.env` command and limits.
