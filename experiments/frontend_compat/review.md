# 独立复核与父任务纠正记录

用户授权 pi 协助实现和独立验收。复核分别进行路线选择、完整语法补丁、词法错误保护三项，均收取通过结论；实现者与复核任务相互独立。

- 路线复核确认官方 Expr 是封闭枚举；忠实保留旧 Loop/Question 需要同一份 AST 及其生产者。采用固定 0.4.0 子集和 0.3.0 的两个产生式，避免整套旧核心或大范围 AST 转换。
- 完整补丁复核对照两个原始官方归档，核验字段、位置、优先级、标签、first-set/恢复分支、JSON 和两个访客；未发现最终阻塞。父任务修复了审查期间发现的包配置格式化导致锁不匹配、通知文件循环覆盖二进制名的问题。
- 父任务通过额外编译器反例发现官方入口忽略词法错误；修复后单独复核确认两个解析器及共享回退均保留错误。直接解析器、CLI 和真实编译器负例通过。
- 词法复核建议补充非法插值测试。父任务新增后实际发现原插值重新词法分析遗漏 `name`，错误文件名为空；添加 `name=source.loc.start.fname` 后用同一失败反例验证文件名与行号。

纠正独立报告中的文字误差，以已提交原始证据为准：

1. 完整补丁报告曾把 `top.mbt` 列为未修改；最终它包含明确的词法错误保留修改，已进入补丁、来源锁及 NOTICE。未修改的是 yacc 生成表/语法。
2. QuickCheck/bitflow 共 46 个文件，官方与兼容 AST 相等的是此前已解析的 41 个，另 5 个是新增解析。加上 core/actrun 对照后，共 581 个既有文件 AST/位置一致。
3. 默认 `frontend_export` 是未修改官方前端的实验对照入口，不属于生产扫描；`--compat` 才使用兼容 Handrolled。生产扫描、插值展开和原生语义入口通过共享兼容前端。
4. 独立报告中的临时测试时间戳和本地缓存可用性不作为验收依据。最终全目标测试、固定源码报告及 PR 的三平台 CI 结果分别保存，未运行项不推断为通过。
